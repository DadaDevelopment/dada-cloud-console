# H05 — capability-матрица RU-конкурентов (long-running workload gap)

Дата замера: 2026-08-15. Метод: документация/changelog/тарифные страницы конкурентов, не лендинговый маркетинг (лендинги использованы только как fallback, помечено явно). Каждая ячейка со ссылкой на первоисточник; где подтверждения не нашли — `unknown` (это НЕ равно "не поддерживает").

Легенда: `yes(src)` = подтверждено источником, `no(src)` = явно исключено источником, `unknown` = не нашли ни подтверждения, ни опровержения за отведённое время.

## Что НЕ удалось заземлить (честный список)

- **Beget Cloud Apps**: не нашли официального продукта с git-автодеплоем уровня Vercel/Railway. Есть маркетплейс VPS-приложений (включая сторонний self-hosted Coolify) — это другая товарная категория (пользователь сам администрирует VPS), а не managed PaaS. Все 12 критериев для Beget — `unknown`, конкурент по факту не подтверждён как относящийся к этому классу.
- **deploy-f.com**: за отведённое время поиск не дал ни одного релевантного результата про сам сервис (запрос вернул общие статьи про cron+Docker). Возможно домен не существует/не индексируется под этим именем, либо название неточное. Все критерии — `unknown`, требует ручной проверки по прямому URL, если он есть в других материалах команды.
- Ряд ячеек Amvera/Timeweb помечены `unknown`, потому что WebSearch summary отдавал общие обзорные страницы, а не точную докс-строку (websocket для обеих платформ, точная сетка RAM/CPU дешёвого тарифа Timeweb, preview-окружения для обеих). Это дыры замера, не факты об отсутствии — следующий шаг ("шаг 1.5") — руками зайти в докс.amvera.ru/поиск по сайту и timeweb.cloud/docs/apps и закрыть именно эти строки, а не расширять матрицу вширь.
- Цена входа Amvera (170 руб.) и заявление "без cold start" опираются на вторичный агрегатор (toolfox.ru), не на официальную тарифную страницу — при фетче официальной amvera.ru/cloud эта формулировка не подтвердилась текстом. Понижено до "требует сверки", не выдано как факт.

## Вывод по H05

**Данных достаточно для частичного, но не полного вывода.**

1. **Gap подтверждается на одном полюсе явно**: Onreza — это НЕ конкурент в классе "долгоживущий процесс + Postgres рядом". Их архитектура request-scoped (Edge isolates с 30-сек таймаутом, SSR на Bun), собственная документация не содержит ни произвольного Docker, ни воркеров, ни compose, ни websocket. Onreza — serverless-центричная платформа, ровно тот профиль, для которого H05 постулирует gap. Здесь гипотеза **не опровергнута** — данные её поддерживают.

2. **Gap НЕ подтверждается на другом полюсе**: Amvera и Timeweb Cloud Apps оба явно поддерживают произвольный Docker, long-running процессы, cron, managed Postgres/Redis — то есть базовый класс "долгоживущий процесс любого стека + Postgres рядом" **уже закрыт минимум двумя RU-конкурентами** на уровне документированных возможностей. Amvera прямо противопоставляет себя serverless-биллингу конкурентов (поминутная оплата работающего контейнера, боты как первоклассный юзкейс). Timeweb дополнительно закрывает multi-service через docker-compose, чего нет у Amvera (там compose explicitly `no`).

3. **Различие внутри "закрыт" не нулевое** — это не одна и та же полка: Amvera не поддерживает docker-compose (единственный Dockerfile), Timeweb поддерживает. Если клин Dada Cloud — "любой стек + compose из нескольких сервисов", то Amvera всё ещё имеет дыру, которую можно бить; если клин — просто "не serverless, Postgres рядом", то оба конкурента уже там.

4. **GitVerse/SourceCraft и preview-окружения расслаивают конкурентов иначе, чем ожидалось**: Onreza (serverless) и предположительно Timeweb — единственные с явной поддержкой GitVerse/SourceCraft и preview per branch/MR; Amvera явно этого не имеет (только GitHub/Bitbucket в доках). Это значит, что "суверенный git" и "preview" — не признаки лагеря serverless vs long-running, а отдельная ось дифференциации, где Amvera слабее обоих других игроков.

**Прямой ответ на H05, шаг 1**: gap в самой примитивной формулировке ("нужен долгоживущий процесс, серверлесс не подходит") **закрыт** Amvera и Timeweb — это НЕ пустая ниша. Оставшийся правдоподобный клин — комбинация полосы, которую ни один конкурент не покрывает целиком по данным этой матрицы: **compose из нескольких сервисов + managed Postgres рядом + GitVerse/SourceCraft + preview-окружения за один продукт**. Ни Amvera (нет compose, нет GitVerse), ни Timeweb (нет подтверждённых preview, cron/GitVerse требуют доверификации), ни Onreza (нет долгоживущих процессов вообще) не закрывают весь список одновременно. Но это вывод про КОМБИНАЦИЮ фич, не про существование ниши "долгоживущий процесс" саму по себе — та уже занята.

**Шаг 2 (спрос) остаётся полностью нетронутым** — эта матрица не говорит ничего про то, сколько RU-разработчиков реально упираются в лимиты Onreza-класса платформ и ищут альтернативу, и сколько из них удовлетворены Amvera/Timeweb. Это отдельный замер (win/loss, форумы, "мигрировал с X потому что Y").
