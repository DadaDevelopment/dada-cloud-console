# AI Studio — v1 design

Status: **Shipped** (2026-05-22)
Date: 2026-05-22
Related: ADR-008 (KServe), ADR-001..006 (console), `dada_cloud_console_adr_prd_v_1_roadmap.md` §v4.3 (pulled forward)
Crossplane XRD: `argo-infra/helm/crossplane-platform-api/templates/crds/aimodel-xrd.yaml`

---

## 1. Understanding summary

- **What.** AI Studio is a new top-level area in DADA Cloud Console for deploying and using AI models. v1 covers MLflow registry browse, deploy (`AIModel` XRD → KServe), embedded production ingress (`PublicApi`), an inference playground, and KServe-native canary rollouts. AIModel sits as a peer of App, optionally attachable, scoped under project + environment.
- **Why.** ADR-008 chose KServe + MLflow + Crossplane as the inference stack and the XRD is shipped. Without console support only platform engineers can ship models, which contradicts ADR-001's "cloud-like self-service" thesis. This pulls roadmap v4.3 forward because the platform abstraction is ready.
- **Who.** Same three roles as the rest of the console — clients, developers, platform admins (per ADR-005).
- **Operating model.** Reuses the existing typed-action / Operation / gitops-agent / Argo CD pipeline (ADR-001..004). Six typed actions; inference is a non-Operation backend proxy.
- **Key constraints.** No raw YAML for clients (named profiles only). No autoscaling in v1 (fixed 1 replica). Stage auto-derived from environment, hidden. Default auth = API key, JWT optional, public requires admin approval. GPU deploys gated by approval + per-project quotas + advisory monthly inference budget. Shared S3 bucket with backend-enforced path-prefix isolation per project. Inference proxy is a transparent passthrough.
- **Non-goals for v1.** No observability cards or log tail (defer to v2). No HPA / autoscaling tuning. No multi-app inference graph. No model evaluation / drift detection. No retraining or fine-tuning UI.

## 2. Assumptions

1. **MLflow is already deployed** and reachable from the backend with credentials available. *Verify before kickoff — if false, scope doubles.*
2. **`WaitingForApproval` state exists** in the operation enum; UI for it is built here (first consumer).
3. **`projects.quotas` does not yet enforce anything.** AI Studio adds the first real quota check via a new `project_quotas` table.
4. **Monthly inference budget is advisory.** The backend proxy is the only counter source in v1; production traffic via `PublicApi` is uncounted until v2 metrics ingestion.
5. **`model-storage` SA is pre-provisioned in every project namespace** by Crossplane / namespace bootstrapper. The console doesn't render it.
6. **MLflow registered-model versions are stable enough to pin** — `PinAIModelMlflowVersion` resolves name+version → S3 artifactURI at render time.
7. **Profile catalog is config**, not a CRD. Lives in backend YAML; edit = redeploy backend.
8. **Status aggregation reuses `resource_snapshots`** — `gitops-agent` status reader pulls AIModel `.status.phase` and `.status.url`.
9. **Playground forwards as the console user.** Backend uses the per-model API key server-side; the user never sees the key during a proxy call.

## 3. Architecture overview

```
Frontend (Next.js)
  (console)/ai-studio                     -- cross-project registry browse
  (console)/projects/.../models           -- per-project deploy/manage
            │
            ▼  REST  /api/v1
backend (Go / Gin)
  ├─ api/aimodels.go     typed operations
  ├─ api/mlflow.go       proxy
  ├─ api/inference.go    proxy
  ├─ api/approvals.go    admin approve/reject
  ├─ api/quotas.go       project quotas + counters
  └─ models/aimodel.go   payload structs
            │
            ▼  Operation row
        Postgres
            │
            ▼  picked up
gitops-agent
  └─ renderer/aimodel.go  → AIModel CR + PublicApi CR → commit to state repo
            │
            ▼  Argo CD watches
Crossplane composes → KServe InferenceService + PublicApi gateway route
            │
            ▼  status.phase / status.url → resource_snapshots
```

Three new flows:

1. **Deploy.** Typed action → Operation → renderer → 2 CRs in Git → Argo → status reader. Identical shape to `ServiceDatabase`.
2. **Registry browse (read).** Backend proxies MLflow REST. No Git, no Operation. Project-scoped path-prefix filtering.
3. **Inference (read).** Backend proxies `POST` to KServe in-cluster URL. No Git, no Operation. Per-call counter; API key injected server-side.

**Approval flow** is shared infrastructure — the admin "Operations awaiting approval" page is built generic. AI Studio is the first consumer; v2 features (restore-over-prod, secret rotation) inherit it.

## 4. Data model

Migration `006_ai_studio.sql`. Forward-only, additive.

### `aimodel_api_keys`

Per-model API key for the embedded `PublicApi`.

```
id              uuid pk
project_id      uuid fk
environment_id  uuid fk
aimodel_name    text
key_prefix      text          -- first 8 chars, displayable
key_hash        bytea         -- argon2id of full key
created_at      timestamptz
revoked_at      timestamptz null
unique (project_id, environment_id, aimodel_name) where revoked_at is null
```

### `aimodel_inference_counters`

Bucketed call counters for the advisory monthly budget.

```
project_id      uuid
year_month      char(7)       -- '2026-05'
aimodel_name    text
environment_id  uuid
call_count      bigint
last_called_at  timestamptz
pk (project_id, year_month, aimodel_name, environment_id)
```

### `project_quotas`

```
project_id              uuid pk
cpu_model_max           int default 5
gpu_model_max           int default 0       -- zero forces approval for any GPU
monthly_inference_calls bigint default 100000
updated_at              timestamptz
```

### `projects` additions

```
ai_storage_prefix   text          -- 's3://platform-models/<projectId>/'
```

### Operation reuse

Six new actions reuse the existing `operations` table. Payloads in `models/aimodel.go`:

```go
CreateAIModelPayload{ Name, ModelType, Source (mlflow|s3|custom), MLflowName, MLflowVersion,
                      ArtifactURI, ContainerImage, Profile, AuthMode, AttachedAppName }
UpdateAIModelArtifactPayload{ Name, ArtifactURI | (MLflowName, MLflowVersion) }
SetCanaryTrafficPayload{ Name, TrafficPercent }
PromoteAIModelPayload{ Name }
DeleteAIModelPayload{ Name, Force }
PinAIModelMlflowVersionPayload{ Name, MLflowName, MLflowVersion }
```

## 5. API surface

Under existing `/api/v1` prefix.

### Typed operations

```
POST   /projects/:p/environments/:e/models                    CreateAIModel
PATCH  /projects/:p/environments/:e/models/:name/artifact     UpdateAIModelArtifact
PATCH  /projects/:p/environments/:e/models/:name/canary       SetCanaryTraffic
POST   /projects/:p/environments/:e/models/:name/promote      PromoteAIModel
DELETE /projects/:p/environments/:e/models/:name              DeleteAIModel
PATCH  /projects/:p/environments/:e/models/:name/mlflow-pin   PinAIModelMlflowVersion
```

`CreateAIModel` with a `gpu-*` profile (or any time `gpu_model_max=0` for the project) lands in `WaitingForApproval` instead of `Created`. Backend logic, not a different endpoint.

### Read endpoints

```
GET    /projects/:p/environments/:e/models
GET    /projects/:p/environments/:e/models/:name
GET    /projects/:p/environments/:e/models/:name/api-key?reveal=true
GET    /projects/:p/quotas
```

### MLflow proxy

```
GET    /api/v1/mlflow/registered-models?project=:p
GET    /api/v1/mlflow/registered-models/:name/versions
GET    /api/v1/mlflow/registered-models/:name/versions/:v
```

Filtered to entries whose `source` (or `storageLocation`) is inside the caller's `ai_storage_prefix`.

### Inference proxy

```
POST   /api/v1/projects/:p/environments/:e/models/:name/infer
```

Forwards to KServe v2 `/v2/models/:name/infer` (or v1 `/v1/models/:name:predict`, auto-detected). Backend injects the per-model API key, increments `aimodel_inference_counters`, transparent passthrough otherwise. Authorisation is the caller's session JWT (project membership check).

### Admin approval (shared infra)

```
GET    /api/v1/admin/operations?status=WaitingForApproval
POST   /api/v1/admin/operations/:opId/approve
POST   /api/v1/admin/operations/:opId/reject
```

## 6. Renderer and Git layout

### Git path

```
clusters/<cluster>/projects/<project>/environments/<env>/
  models/
    <model-name>/
      aimodel.yaml      -- AIModel CR
      publicapi.yaml    -- PublicApi CR
```

Same shape as `apps/<name>/{app.yaml,database.yaml,endpoint.yaml}`. Argo CD already watches the tree.

### `gitops-agent/internal/renderer/aimodel.go`

```go
type AIModelInputs struct {
    ProjectSlug string
    EnvSlug     string
    Namespace   string         // <project>-<env>
    Name        string
    ModelType   string         // sklearn | pytorch | huggingface | ...
    Version     string
    Stage       string         // dev->development, prod->production
    ArtifactURI string         // resolved s3://...
    Profile     string         // cpu-small | gpu-t4 | ...
    Container   *ContainerSpec // when modelType=custom
    Canary      *int           // 0..100; omitted when 100 / absent
    APIKeyRef   string         // secret name backing PublicApi auth
    Owner       OperationMeta  // commit metadata
}
```

Emits AIModel using XRD field names directly: `modelType`, `artifactURI`, `resources`, `autoscaling.{min,max}=1`, `canary.trafficPercent` (only when set), `storage` left at XRD defaults. Reuses the existing `endpoint.go` renderer for the `PublicApi` CR with `auth.mode=apikey` and the per-model secret.

**Determinism.** Identical inputs → identical YAML → empty diff → no commit. Reuses the existing renderer's content-hash gate.

**Concurrency.** Operations on the same model serialise via the existing per-resource Postgres advisory lock (already used for `ServiceDatabase`).

## 7. Screens

### S1 — `(console)/ai-studio` — registry browser
Cross-project list of MLflow registered models the user can access (filtered by `ai_storage_prefix`). Columns: name, latest version, modelType (from MLflow tags), last updated, "Used by" count. Row click → version drawer. Action: *Deploy this version* → routes to S3 with prefilled fields. Visible to all roles.

### S2 — `(console)/projects/[p]/environments/[e]/models` — project list
Card grid. Each card: name, modelType badge, profile badge, canary % bar if active, status pill (Pending / Ready / Failed). *Create model* CTA. Empty state explains the registry → deploy flow.

### S3 — Create wizard (modal route)
1. **Source** — MLflow registered model + version, OR pasted artifactURI (validated against project prefix), OR `custom` container image.
2. **Identity** — name (k8s-validated), attach to App (optional dropdown).
3. **Compute profile** — radio of cpu/gpu profiles. GPU rows show "Requires admin approval" when `gpu_model_max=0`.
4. **Public access** — auth mode (apikey default, jwt option, public disabled with admin-only tooltip), domain prefix preview.
5. **Review & deploy** — diff-style summary, *Create* button → `POST /models`.

### S4 — Model details
Tabs:
- **Overview** — status, replicas, KServe URL, attached App, canary %, *Promote* / *Set canary* actions.
- **Versions** — current artifactURI / MLflow pin, *Update artifact* form, history table from `operations`.
- **Access** — auth mode, masked API key prefix, *Reveal once* button → one-shot modal.
- **Playground** — see S5.
- **Operations** — filtered timeline.
- **Manifests** (admin only) — generated YAML, Git path, Argo app, Crossplane composite name.

### S5 — Playground
Per-modelType widgets: chat textarea (`huggingface`), tabular feature builder (`sklearn`/`xgboost`/`lightgbm`), JSON editor (`pytorch`/`tensorflow`/`triton`), drag-drop file upload for vision/audio routed via `multipart` → backend → KServe. Response panel: pretty JSON, rendered text, decoded label/score per type. *View as raw JSON* toggle. *Send* disabled when status ≠ `Ready`. Shows monthly call counter ("1,243 / 100,000 advisory cap").

### S6 — Approvals (admin) `(console)/admin/approvals`
Generic table of operations in `WaitingForApproval`. Approve / Reject (with reason). v2 dangerous actions inherit this without UI changes.

### Project overview additive widget
Quotas widget on `(console)/projects/[p]`: cpu_model usage / gpu_model usage / monthly inference calls — reads `GET /projects/:p/quotas`.

## 8. Security, RBAC, error handling, edge cases

### Security boundaries

- No browser → MLflow / KServe direct. Both go through backend (NFR-002).
- **Path-prefix isolation.** `CreateAIModel` rejects any `artifactURI` not starting with the caller project's `ai_storage_prefix`. MLflow proxy filters out registered models whose source falls outside.
- **API-key reveal.** Plaintext is generated once at worker time, hashed (argon2id) into `aimodel_api_keys`, and the plaintext is parked in a short-lived (15 min) Postgres row keyed by operation ID. `GET /api-key?reveal=true` consumes and deletes that row. After 15 min the key is permanently unrecoverable — only rotate.
- **Inference proxy auth.** Caller's session JWT for authorization (project membership). The model's API key is server-side only; if the cache is cold (e.g. backend restart between issuance and reveal), proxy returns 503 with "Rotate the API key to re-enable proxy".
- **Approval bypass prevention.** The approval transition is the only way `gpu_model_max=0` operations leave `WaitingForApproval`. Audit row references both actor (admin) and original requester.

### RBAC matrix

| Action | client-viewer | client-admin | developer | platform-admin |
|---|---|---|---|---|
| List models / open playground | ✓ | ✓ | ✓ | ✓ |
| Create CPU model | – | ✓ | ✓ | ✓ |
| Create GPU model | – | request → approval | request → approval | ✓ direct |
| Update artifact / set canary / promote | – | ✓ | ✓ | ✓ |
| Reveal API key | – | ✓ (own project) | ✓ | ✓ |
| Delete model | – | ✓ | ✓ | ✓ |
| Approve operations | – | – | – | ✓ |
| View Manifests tab | – | – | – | ✓ |

### Error handling

- **MLflow unreachable** — registry banner + wizard falls back to "paste artifactURI".
- **KServe URL not yet populated** — playground disabled with "Model is starting"; details page shows phase from `resource_snapshots`.
- **Quota exceeded at submit** — `409 Conflict`, `error_code=quota_exceeded`, payload includes `current/limit/upgrade_path`.
- **Concurrent canary edits** — second op gets `409` if the first is still committing.
- **Budget counter overage** — non-blocking; UI shows "over advisory cap" badge.

### Edge cases

- **Custom container with no artifactURI.** XRD allows it; renderer emits `container.image` and skips `artifactURI`.
- **MLflow run pinned, then run deleted upstream.** Re-resolution fails on next render. Operation goes `Failed` with actionable error; previous AIModel keeps running because last-good YAML remains in Git.
- **DeleteAIModel with attached App** — `409` until detached, or admin uses `force=true` (audit row written).
- **`auth.mode=public`** — only reachable through admin path. Backend rejects public payloads from non-admins.

## 10. Testing strategy

- **Unit.** Renderer (deterministic YAML for each modelType + profile permutation), validators (artifactURI prefix, kube name, quota math), proxy (multipart routing, KServe v1/v2 path detection).
- **Integration.** Full `CreateAIModel` operation against Postgres + fake gitops-agent + mock MLflow + mock KServe; happy path and `WaitingForApproval` branch.
- **Manual E2E.** Deploy a sklearn model from MLflow → playground call → set canary → promote → delete. One run on beget-prod before declaring v1 done.
- **Approval regression.** Existing operation tests must still pass; approval logic only triggers on the GPU branch.

## 11. Implementation phases

Each phase landed as an independently shippable commit on `main`. The
`AI_STUDIO_ENABLED` flag defaulted to **off** through phases 1–7 so
nothing was visible to users until phase 8 flipped the default.

1. ✅ **Migration `006_ai_studio.sql`** — additive: `aimodel_api_keys`,
   `aimodel_api_key_reveals`, `aimodel_inference_counters`,
   `project_quotas`, `projects.ai_storage_prefix`.
2. ✅ **Backend AIModel CRUD + MLflow proxy + Quota.** Six typed
   actions, profile catalog, validators, GPU-approval branch.
3. ✅ **Renderer + gitops-agent path.** `aimodel.go` + dispatcher;
   embedded `PublicApi` rendered alongside in the same operation.
4. ✅ **Frontend S2 / S4-Overview.** Project model card grid + details
   page with status / source / traffic panels.
5. ✅ **Approval admin S6.** Generic table at `/admin/approvals`;
   Approve transitions to `Created`, Reject to `Cancelled` with reason.
6. ✅ **Playground S5 + inference proxy + counters.** modelType-aware
   widget; transparent KServe v1/v2 passthrough; UPSERT counter.
7. ✅ **Registry browser S1 + tabbed S4.** `/ai-studio` cross-project
   MLflow browser with prefill links into the project wizard. S4 split
   into Overview / Versions / Access / Playground / Operations /
   Manifests (admin-only) tabs.
8. ✅ **Lift feature flag.** `AI_STUDIO_ENABLED` default flipped to
   `true`. `false` remains as a runtime kill-switch.

Each phase is reversible: flag off + revert frontend route. Rollback
for phase 1 is a forward-compat migration since the columns/tables are
unused outside AI Studio code paths.

## 12. Risks

- **MLflow availability assumed.** Verify before kickoff; if false, phases 1–4 still ship but phase 7's registry browser becomes a "paste URI" fallback.
- **API key recoverability** — backend restart between issuance and reveal loses the plaintext. Mitigation: documented rotate path. Real fix in v2 (proper secret store integration).
- **Budget counter undercounts.** Production traffic via `PublicApi` bypasses the proxy. Documented as advisory-only until v2 metrics ingestion.
- **Approval-state UI is new.** First consumer of `WaitingForApproval`. If the UX is wrong, all v2 dangerous-action features inherit the problem. Build it generic, review carefully.
