# agentkit

Общий слой для наших агентов. Сюда попадает то, что уже понадобилось дважды;
всё остальное живёт в самом агенте, пока не понадобится.

Статус: обёртка. Кандидат в платформу, но ещё не проверен на клиентском репо.
Разметка кусков и обоснование — `../docs/PLATFORM-DOGFOODING.md`.

| Модуль | Что делает |
|---|---|
| `humanize.py` | Ищет AI-метки в короткой реплике: слоп-фразы, разметка в чате, длинное тире, невидимый юникод, длина. Без модели |
| `evalspec.py` | Формат золотого набора (JSONL), валидация, раннер, сводка, гейт по сплиту |
| `ledger.py` | Правило журнала ответов: `answered` без текста запрещён, молчание пишется словом `SKIP` |
| `skills.py` | Загрузка `agents/<имя>/core.md` и `domains/<домен>.md`, та же раскладка, что читает Go-рантайм |
| `gate.py` | Прегейт по одному агенту, когда пути передали снаружи: золотой набор, гигиена промпта, дерево скиллов |
| `repospec.py` | Тот же гейт, но пути берёт из `.dada/agent.json` в репозитории. Это и есть контракт для клиентского репо |

Зависимостей нет, только стандартная библиотека.

```bash
cd agentkit && python3 -m unittest discover -s tests -q
python3 repospec.py --repo ..
```

Контракт репозитория и то, что проверяется, расписаны в
`../docs/AGENT-REPO-SPEC.md`. Наш собственный монорепо выполняет его целиком, и
тест `test_repospec.TestThisRepoSatisfiesTheSpec` следит, чтобы это не стало
неправдой: спека, которую не выполняет её автор, это не спека.

## Доставка ответа это отдельный отказ

Две живые поломки в `tg-vibecoder`, обе с целым журналом и пустым чатом.

Первая: ход вернул «Ответил.» и записал `decision=answered, reply=''`. Модель
приняла `record_reply` за канал доставки. Вторая: ход решил промолчать,
записал `decision=skipped` правильно и вернул в чат `{"ok":true,"id":3}` -
у A2A нет пустого хода, и то, что модель не написала сама, за неё дописал
результат последнего инструмента.

Отсюда два правила здесь, а не в агенте: `ledger.validate_decision` не даёт
записать ответ без текста, `humanize` валит реплику, которая целиком является
отчётом о работе (`status_instead_of_reply`) или сериализованным результатом
инструмента (`tool_output_as_reply`). Молчание выражается явно:
`ledger.SILENCE_SENTINEL`, и снимает его тот, кто отправляет сообщение.

## Почему правила, а не судья-модель

Проверка, которой нужна LLM, не встаёт в прегейт, не объясняет себя и плывёт
вместе с судьёй. Правило называет конкретный кусок, на котором сработало, и
его можно опровергнуть. Судейская модель имеет смысл поверх, никогда вместо.

## Почему сплиты — не украшение

`dev` для тюнинга, `holdout` для решения. Прогон `holdout` больше одного раза
на ревизию делает из набора зеркало: он начинает мерить подгонку, а не
годность.
