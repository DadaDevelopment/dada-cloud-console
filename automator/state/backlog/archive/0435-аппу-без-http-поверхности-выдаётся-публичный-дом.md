Юзерских аппов «зелёный под, мёртвый URL» -- 4. Механизм порт-мисматча (пункт 0433)
не воспроизводит из них НИ ОДИН: он единичный и наш собственный.

Суть ЭТОГО пункта: `fanvk` и `sevarateambot` -- долгоживущие боты без HTTP-сервера.
Сокета нет не по поломке, а по замыслу. Мы всё равно выдали им публичный домен:
`backend/internal/api/apps.go` `servesHTTP(servicePort)` исключает только известные
порты БД (6379/5432/3306/...), всё прочее считает веб-аппом и вешает хостнейм на
ДОГАДАННЫЙ порт. Дальше домен вечно отдаёт 502, юзер видит красное там, где ничего
не ломалось.

`backend/internal/api/app_url_watcher.go:490-512` этот случай уже осознал и гасит
АЛЕРТЫ через `hasServedHTTP` (апп, ни разу не ответивший по HTTP, алерт не поднимает).
Но выдача домена и блок `live_urls.dead_apps` в `admin_overview.go` того же правила
не знают -- владелец в панели по-прежнему видит эти аппы как мёртвые.

Что сделать: один рычаг «у аппа нет HTTP-поверхности», применённый в трёх местах
одинаково -- выдача домена, алерт, панель.

Приёмка двухполюсная: бот без сокета не получает домен и не попадает в `dead_apps`;
веб-апп, у которого сокет ПРОПАЛ (был и исчез), ОБЯЗАН попасть в оба.

Ловушка: `worker: true` при создании это уже отражает, но `fanvk` создан без него
(port=0 -> догадка 8080). Вывод должен идти из НАБЛЮДЕНИЯ (`hasServedHTTP`), не только
из флага.
