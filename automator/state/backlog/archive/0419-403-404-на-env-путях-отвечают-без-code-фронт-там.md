Заземлено [code, sess-0820i, остаток после af4c27ff].

`af4c27ff` дал `code` пяти локальным хелперам отказа env-подсистемы, но НЕ покрыл пути,
идущие через общие `respondForbidden`/`respondNotFound`:
- RevealEnvVar: не участник проекта (403), read-only роль (403), окружение не принадлежит
  проекту (404), переменная не найдена (404);
- DeleteEnvVar: переменная не найдена (404).

Тело там прежнее `{"error": "..."}` без `code`, поэтому новый словарь
`frontend/lib/env-error.ts` на этих отказах молча уходит в фолбэк `err.message`, и юзер
снова видит фразу без следующего шага. Для 403 фронт спасает костыль
`status === 403 && !describeEnvError(code)` — то есть ровно тот класс, который чаще всего
и встречает человек с read-only ролью.

Работа: дать `respondForbidden`/`respondNotFound` (или их env-вызовам) машинный код и
дописать эти коды в словарь фронта.

M2: отказ по каждому из пяти путей несёт `code` в теле, а форма показывает причину и
следующий шаг, а не фолбэк.
