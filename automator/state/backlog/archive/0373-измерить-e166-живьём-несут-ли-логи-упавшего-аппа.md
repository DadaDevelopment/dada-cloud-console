`Level:"ERROR"`, а идёт тремя ярусами (ERROR/час → без фильтра/час → без фильтра/24ч).

НЕ ИЗМЕРЕНО живьём: сама посылка. Egress машины умер в этом цикле (VPN-туннель режет
TCP SYN к прод-IP, обходной `en0` — телефонный хотспот без бэкхола), поэтому ES не
опрошен. Фикс доказан поведенческим RED/GREEN на фейковом бэкенде поиска, не
выздоровлением аппа.

Что прогнать, когда есть доступ:
1. Два запроса к ES-индексу инфра-логов по `gulyaev-ai-core`
   (ns `lifecoachrussia-yandex-ru-prod`) за час: с `level=ERROR` и без. Числа документов
   + есть ли строка `ModuleNotFoundError` в каждой выдаче. Какое реально значение полей
   `level`/`app.level` у строк этого пода (или полей нет вовсе).
2. `resource_snapshots.summary_json` этого аппа: появился ли `cause_kind`/`cause_line`.
3. После выката образа — доля вызовов авто-фикса с непустым лог-контекстом.

Развилка: если логи ЭТОГО аппа несут `level=ERROR`, правка для него no-op, и причину
провала авто-фикса искать в другом (окно 1ч, Size 50, либо качество самого агента) —
тогда завести отдельный пункт и не считать H08 продвинутой.
