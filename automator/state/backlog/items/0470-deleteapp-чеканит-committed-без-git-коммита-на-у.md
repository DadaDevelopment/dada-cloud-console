[live psql `audit_events` + `operations`, окно 14д, замер E97/E98/E99 этого цикла]

`kkartov@yandex.ru` / апп `instatic`, 08-17 -> 08-19: **9 успешных `DeleteApp` против 3
`CreateApp`**, у 6 из 9 `git_commit` ПУСТОЙ. То есть удаление возвращает `Committed`/success,
не сделав ни одного коммита в git, на уже отсутствующем ресурсе - честный no-op, посчитанный
как новый успех.

Это НЕ закрытые механизмы:
- teardown `git_repos` (`d5232a5a`) - закрыт, к этой сигнатуре не относится;
- видимость orphan (`68b5dfbd`) - 0 строк Orphaned, слой держит;
- реплей истории (`3a7a7522`) - 0 вставленных снапшотов `App` с 08-08, гейт чистый
  (холодный старт gitops-agent 2026-08-21T22:47:59Z внутри окна, значит ноль честный).

Третий, неописанный путь. Продуктовый вред сейчас ограничен: юзер фантомных аппов не видит и
за них не платит - шум бэкенда, а не UI. Поэтому adjust, а не P0. Но метрика «повторные
успешные DeleteApp» останется грязной, пока путь не назван: любой будущий замер надёжности
удаления будет считать no-op успехом.

Чинить: `DeleteApp` обязан различать «удалил» и «удалять было нечего», и не чеканить
`Committed` без git-коммита (родственно уже описанному
`project_deleteapp_reported_success_without_git_commit`).
