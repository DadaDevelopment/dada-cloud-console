Вскрыто при закрытии 0388 (sess-0820f). `git-oauth-flight.sql` меряет пару
`StartGitAppInstall`/`FinishGitAppInstall`, то есть ТОЛЬКО перелёт установки GitHub App. Но
`linkGitRepo` (`backend/internal/api/gitrepos.go:1409+`) принимает пустой `installation_id` и
собирает анонимный `https://github.com/<repo>.git` — этот путь подключает публичный репозиторий
БЕЗ App и не пишет ни одной строки перелёта.

Цена: `kkartov@yandex.ru` подключил репозиторий шесть раз и по нашей метрике не подключил ни разу
(0 строк в `git_app_installations`, 0 Finish любого исхода). Число «дверь теряет 91.7%» описывает
смертность ОДНОГО из двух механизмов и молча выдаётся за смертность двери.

Что сделать: инструментировать анонимный путь тем же вердиктом (или отдельным `flow=public_clone`),
после чего пересчитать смертность по обоим путям вместе. До этого любую правку «двери»,
приоритизированную по 91.7%, считать необоснованной.

M2: запрос по обоим flow даёт число подключённых репозиториев, совпадающее с числом строк
`git_repos`, созданных живыми акторами за то же окно.
