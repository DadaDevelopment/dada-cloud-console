Корень — `backend/internal/api/gitrepos.go:1089-1090`: `if req.Port == 0 { req.Port = 8080 }`, порт ВЫДУМЫВАЕТСЯ, а `renderer.go:391` превращает выдумку в `service.enabled: true`. Также опровергнут `readinessProbe`: NotReady → `livePhase` даёт `Pending` (`gitops-agent/internal/worker/statusreconciler.go:1021-1032`) → жёлтый бейдж без баннера и письма, И апп ВЫПАДАЕТ из `WHERE rs.phase='Ready'` в `backend/internal/api/app_url_watcher.go:130`, теряя url-алерт, который у него есть сегодня — чистый регресс. Работает только `startupProbe` (`tcpSocket`), потому что его провал даёт CrashLoopBackOff, который уже ловит `detectPodAlert` (`app_health_watcher.go:382`) → `app_health_alerts` → баннер + письмо, без единой строки нового кода. **Путь, который остаётся:** (а) влить ИНЕРТНЫЙ патч чарта `healthcheck: "tcp"` + `tcpProbes` + пересчёт `progressDeadlineSeconds` (дефолт 240 меньше стартового бюджета 610с → Argo покажет Degraded на здоровом аппе) — побайтная идентичность рендера без нового значения ДОКАЗАНА прогоном на 5 наборах values; (б) попутно починить мину: `healthcheck: true` без кавычек СЕГОДНЯ роняет рендер (`incompatible types for comparison: bool and string`, `deployment.yaml:476`), схема такое значение пропускает — лечится `toString`; (в) включать `tcp` ТОЛЬКО когорте аппов, чей публичный URL хоть раз ответил HTTP (нужен `last_success_at` в `app_url_alerts` — сейчас успех просто DELETE-ит строку, `app_url_watcher.go:277`); (г) ✅ ОТГРУЖЕНО sess-0806l (`c94fb7ec`): корневой фикс — порт больше не выдумывается, у импорта репозитория есть переключатель «фоновый процесс», `worker=true` доносит порт 0 до `git_repos`, CreateApp и build-agent его не переподставляют. ⚠️ Патч живёт в `dada-argo`, где сейчас НЕКОММИЧЕННЫЙ диф параллельной сессии по `service.enabled` — он предусловие, класть сверху, чужое не трогать (M3).
