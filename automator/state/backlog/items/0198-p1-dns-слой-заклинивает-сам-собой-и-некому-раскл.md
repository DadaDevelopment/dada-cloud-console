      ✅ **КОРЕНЬ ЗАКРЫТ sess-0807f, 2026-08-07 03:29Z, argo-infra `ff35237` (ветка `console-migration`)** — и он оказался НЕ тем, что записано ниже. Гонка с eventually-consistent Beget была следствием, а причиной был самокормящийся шторм CREATE. `isRemovedCheck` (`publicapi-composition.yaml:46`) считал запись удалённой при ЛЮБОМ ответе без `answer.result.records.A`; троттл-ответ Beget `{"status":"error","error_code":"LIMIT_ERROR"}` имеет ровно такую форму → provider-http решал «записи нет» → слал ещё один CREATE в `dns/changeRecords` → жёг квоту → получал следующий троттл. Замерено [live]: `oxygen-30815d` (брошенный апп `good.win2283@gmail.com`) накрутил **56.5к поколений за 8 суток** — запись в API Beget примерно раз в 12 секунд, при том что `--poll=30m`. В момент разбора **49 из 51** Request держали в теле ответа `LIMIT_ERROR`: весь DNS-контур платформы был зарейтлимичен нами же.
      Фикс — одна строка: предикат теперь начинается с `.response.body.status == "success" and (...)`, то есть ошибочный ответ читается как «не удалено» и не запускает починку, которая помочь не может.
      **M2 снят на проде [live, 03:29-03:35Z]:** прирост `generation` у `oxygen` = **0 за 300 секунд** (до фикса +4 за 30с); его condition впервые за 8 суток `Ready=True Available`; по флоту **50 из 51** Request перешли в `Ready=True Available` (до фикса 50 из 51 висели `Ready=False Creating`, самые старые — два месяца). DNS цел: `console/cloud/auth/fanvk` → 155.212.223.198 c ns2.beget.ru, `console.dada-tuda.ru/login` = 200.
      НЕ закрываю пункт целиком — остаются два хвоста, оба НЕ взяты по правилу одного яка: **(а)** подметателя залипших MR по-прежнему нет (нужен как страховка от любой другой заклиненной MR, не только этой); **(б)** у 4 удалённых аппов A-записи живут в Beget (`fan-e8caf6`, `fonbet-value-git-ai-cloud-task-f2d717`, `static-starter-demo-e9ddb6`, `agent-orchestrator-ui-4ad07d`) — k8s расчищен, внешний DNS нет. Плюс два дефекта, найденных попутно и записанных в коммит: `UPDATE`-mapping и `expectedResponseCheck` отсутствуют (запись с ЧУЖИМ значением починить в принципе нечем), а `isRemovedLogic` хардкодит `records.A` и игнорирует `recordType`.
      Историческая формулировка (причина указана неверно, оставлена для сверки): 🔴 P1-DNS-СЛОЙ-ЗАКЛИНИВАЕТ-САМ-СОБОЙ-И-НЕКОМУ-РАСКЛИНИТЬ (sess-0807c, 2026-08-07, [live kubectl 36/36]) — прямое продолжение закрытого P1 про неубираемый апп. Ручная расклинка сработала, но причина осталась: любой `Request` beget-dns после успешного CREATE получает `external-create-pending` новее `succeeded` (гонка с eventually-consistent Beget: `changeRecords`→success, следующий `getData` записи не видит, `isRemovedCheck` говорит «нет записи», Crossplane идёт CREATE второй раз). Замер: 36 из 36 живых Request были в этом состоянии, разрыв pending−succeeded 40-90 сек, самый старый висел 15 суток. Пока это так, **каждое следующее удаление аппа снова зависнет навсегда**, и никто этого не увидит — алерта нет, консоль показывает апп удалённым, ресурсы живут.
      Два независимых дефекта, чинить оба: **(1)** гонка на CREATE — вылечить композицией: `expectedResponseCheck`/`isRemovedCheck` не должны считать «только что созданную» запись отсутствующей (кандидат — считать CREATE успешным по телу ответа `answer.result==true`, а не по последующему OBSERVE). Живёт в argo-infra (composition `publicapi-beget-dns`), ветка `console-migration`. **(2)** отсутствие подметателя — CronJob, который раз в 10-15 мин находит MR с `Synced=False` и `reason=ReconcileError` + сообщением `cannot determine creation result`, снимает `crossplane.io/external-create-pending` **и делает poke-аннотацию** (без poke реконсайлер не просыпается — проверено live: условие висело 9 суток при актуальном `observedGeneration`). Подметатель нужен, даже если (1) вылечит гонку: он же ловит любую другую заклиненную MR.
      Хвост: у 4 удалённых аппов A-записи остались в Beget (`fan-e8caf6`, `fonbet-value-git-ai-cloud-task-f2d717`, `static-starter-demo-e9ddb6`, `agent-orchestrator-ui-4ad07d` → 155.212.223.198 на ns2.beget.ru после удаления объектов) — k8s расчищен, внешний DNS нет. Чистить через Beget API кредами из `beget-dns-credentials`, отдельным шагом и не вслепую.
