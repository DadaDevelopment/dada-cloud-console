# Объектное хранилище S3

## Зачем это нужно

S3-совместимый бакет (на инфраструктуре Beget) для медиафайлов, статики и бэкапов. Работает
с любым S3-клиентом: `aws-cli`, `s3cmd`, boto3, minio-sdk — отдельного API учить не нужно.

## Как создать бакет

1. Откройте **Object Storage** → **Create Bucket**.
2. Заполните форму:
   - **Resource Name** — идентификатор на стороне консоли (строчные буквы, цифры, дефисы).
   - **Bucket Name** — имя самого S3-бакета.
   - **Region** — сегодня доступен только `ru1`.
   - **Description** — необязательно.
   - **App Reference** — необязательно: привязать бакет к конкретному приложению или
     оставить пустым, чтобы он жил на уровне окружения.
   - **Public Access** — переключатель, разрешает публичные ссылки без подписи.
   - **FTP/SFTP Access** — включает протокол (по умолчанию включён); реквизиты доступа
     консоль не показывает, см. «Подводные камни».
3. Нажмите создать — вас перебросит в **Operations**, где видно ход выделения ресурса.

## Подводные камни

- **Endpoint, access key и secret в консоли вы не получите.** После создания карточка бакета
  показывает только имя, регион и бейджи public/app-ref, кликнуть внутрь некуда. Реквизиты S3
  придётся получить вне консоли — через поддержку или хранилище секретов вашей команды. Эта
  страница не подскажет конкретный путь, потому что интерфейс их не отдаёт.
- Переключатель **FTP/SFTP Access** только выставляет флаг: ни адреса, ни логина с паролем он
  не показывает.
- Карточки бакетов некликабельны — нажатие ничего не делает.

## Чего пока нет

- Страницы бакета с endpoint, ключами и примером команды `aws-cli` или сниппета для SDK.
- Удаления бакета.
- Регионов, кроме `ru1`.
- CDN и версионирования — в этом интерфейсе их нет вообще.
