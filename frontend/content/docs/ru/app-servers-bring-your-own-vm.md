# Подключить свой сервер (App Servers)

## Зачем это нужно

У вас уже есть VPS или железный сервер. Вместо переезда подключите его к Dada один раз по SSH:
платформа поставит Docker и edge-агент, после чего сервером можно управлять и деплоить на него
из консоли, как на любой другой ресурс. Никакое приложение никуда не переезжает.

## Как подключить

1. Откройте **App Servers** → **Add VM**.
2. Задайте **Name** (строчные буквы, в стиле DNS-имени — оно же станет именем endpoint в
   Portainer).
3. В блоке **Source** выберите **Connect existing VM**.
4. Заполните:
   - **VM IP address** — адрес сервера.
   - **SSH port** — по умолчанию `22`.
   - **SSH user** — по умолчанию `root`.
   - **SSH private key** — вставляется прямо в форму. Ключ используется **один раз**, чтобы
     поставить Docker и агент, после чего выбрасывается. Он не сохраняется.
5. Отправьте форму. Статус пойдёт **Provisioning** → **WaitingForAgent** (пока агент не
   отзвонится) → **Ready**, когда Portainer подтвердит heartbeat.

## Подводные камни

- **SSH-ключ нигде не хранится.** Если подключение оборвалось на середине, ключ придётся
  вставить заново. Кнопки «запомнить» нет.
- **У статуса WaitingForAgent нет таймаута и индикатора прогресса.** Если он висит долго,
  проверьте, что VM достаёт до сети платформы и что Docker встал корректно — консоль сама
  причину пока не расскажет.
- **Если подключение упало** (статус **Failed**), на странице сервера есть **Retry connect** —
  вставьте ключ ещё раз. IP в этом окне **только для чтения**: неверный адрес так не
  исправить, сервер придётся удалить и создать заново.
- **Delete** доступен строкой списка App Servers всем, у кого есть право управления. После
  удаления вас перебросит в Operations посмотреть, чем всё кончилось.

## Когда сервер стал Ready

Если на нём уже крутятся контейнеры, идите в
[подключение существующих нагрузок](app-servers-adopt-existing-workloads.md) — они попадут под
управление без пересборки.

## Чего пока нет

- Смены IP у существующего сервера: только удалить и создать заново.
- Видимого таймаута и внятной диагностики, пока сервер висит в `WaitingForAgent`.
- Деплоя нового приложения в VM-окружение со страницы Applications — там это намеренно
  заблокировано, работайте через App Servers.
