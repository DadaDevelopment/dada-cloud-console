# Парк клиентских серверов: сценарий для агентства

## Зачем это нужно

Если вы агентство и держите машины нескольких клиентов, отдельный инструмент на каждого не
нужен. Подключите (или закажите) сервер каждого клиента как отдельный App Server внутри одного
проекта — и получите общий мониторинг, логи и метрики по всем из одной консоли.

Отдельной функции «парк серверов» в интерфейсе нет: ниже описано, как использовать обычный
список **App Servers** в масштабе.

## Как это настроить

1. Для каждой клиентской машины: **App Servers** → **Add VM**, дальше либо
   [подключите существующий сервер](app-servers-bring-your-own-vm.md), либо
   [закажите новый](app-servers-order-a-vm.md) за клиента.
2. Повторите для всех машин. Они окажутся в одной таблице **App Servers** со столбцами
   **Name**, **Status**, **VM IP**, ссылкой на **Portainer** и временем последнего heartbeat.
3. Для машин с готовым compose-стеком используйте
   [подключение существующих нагрузок](app-servers-adopt-existing-workloads.md) — сервисы
   каждого клиента станут отдельно наблюдаемыми приложениями.
4. Поднимите [мониторинг](monitoring-metrics-logs-alerts.md) по каждому приложению: будут
   алерты и дашборды на клиента, которые можно показывать как гарантию надёжности.

## Подводные камни

- Группировки, тегов и подпроектов в списке App Servers сегодня нет — единственный инструмент
  наведения порядка это соглашение об именах, например префикс с именем клиента.
- Доступы в проекте общие: выдать участнику доступ только к одной клиентской машине внутри
  проекта нельзя. Нужна жёсткая изоляция — заводите отдельный проект на клиента, см.
  [участники и роли](members-and-roles.md).
- Удаление машины — действие в строке списка. Проверьте, что удаляете сервер того клиента:
  ничего, кроме стандартного подтверждения, вас не остановит.

## Чего пока нет

- Отдельного мультиарендного вида «парк», тегов клиентов и ограничения доступа по машинам
  внутри одного проекта.
- Массовых операций, например переописи сразу по всем машинам.
