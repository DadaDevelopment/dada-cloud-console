# Заказать виртуальную машину (App Servers)

## Зачем это нужно

Сервера ещё нет и выбирать его не хочется — закажите VM прямо из консоли. Платформа сама
выделит машину и подготовит её: Docker и edge-агент уже внутри.

## Как заказать

1. Откройте **App Servers** → **Add VM**.
2. Задайте **Name** (строчные буквы, в стиле DNS-имени).
3. В блоке **Source** выберите **Provision (Terraform)**.
4. Заполните:
   - **Flavor** — small, medium или large.
   - **Region** — `ru1`, `ru2`, `kz1` или `eu1`.
   - **OS image** — свободное поле, по умолчанию `ubuntu-22.04`.
   - **SSH key name** — свободное поле, по умолчанию `dada-agent`.
5. Отправьте форму. Статус пойдёт **Provisioning** → **WaitingForAgent** → **Ready**, как и у
   подключённого своего сервера.

## Подводные камни

- Этот путь полностью пропускает вставку SSH-ключа: выделение машины и установку агента
  платформа берёт на себя.
- Оговорки по статусам те же, что у своего сервера: у **WaitingForAgent** в текущем интерфейсе
  нет таймаута.
- После заказа сервер управляется одинаково, независимо от способа создания: в списке рядом
  живут и заказанные, и подключённые вручную, у каждого есть **Delete** для тех, у кого есть
  право управления.

## Когда сервер стал Ready

Зайдите на машину по SSH, поднимите свой compose-стек, а затем перенесите контейнеры в Dada
через [подключение существующих нагрузок](app-servers-adopt-existing-workloads.md). Формы
«создать новое compose-приложение» в консоли нет — сегодня compose-приложения попадают в Dada
только через это подключение.

## Чего пока нет

- Выбора образа ОС и SSH-ключа из списка: оба поля свободные, без проверки, что такой образ или
  ключ вообще есть в регионе.
- Пошагового «выкатите первый compose-стек на новую машину» — вы всё ещё заходите по SSH сами,
  а потом подключаете нагрузки.
