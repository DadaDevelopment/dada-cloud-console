# Мониторинг: метрики, логи и алерты

## Зачем это нужно

Понимать, жив ли сервис, видеть, где именно проблема, и узнавать о ней раньше пользователей —
для себя или как гарантию надёжности, которую можно показать клиенту.

## Как настроить

1. Откройте **Monitoring** → **Create Monitoring App** и задайте имя.
2. Сразу появится карточка онбординга из трёх шагов:
   - **Шаг 1** выполняется сам: приложение мониторинга создано.
   - **Шаг 2**: один раз показывается **API-ключ** — скопируйте его сразу. Посмотреть его
     повторно нельзя: потеряли — придётся выпускать новый на странице приложения.
   - **Шаг 3**: сниппеты подключения на вкладках **Node.js**, **Python**, **Env vars** и
     **curl**, уже с вашим ключом и адресом приёмника. Поле `service.instance.id`
     необязательно и становится меткой источника, по которой можно фильтровать.
3. Статус карточки обновляется сам: **Checking…** → **Waiting for first telemetry** →
   **Receiving**. Опрашивается раз в несколько секунд, страницу перезагружать не нужно.
4. Как только данные пошли, откройте приложение: вкладки **Overview** (здоровье, время
   последнего сигнала, доля ошибок за 15 минут, сработавшие алерты), **Metrics**, **Logs**
   и **Alerts**.

## Алерты и уведомления

1. На вкладке **Alerts** приложения добавьте правило: метрика, условие, порог, длительность и
   канал уведомления (или «— none —», чтобы просто фиксировать срабатывание).
2. Каналы уведомлений настраиваются отдельно:
   - **Telegram** — токен бота и chat ID.
   - **Email** — адреса через запятую.
   - **Webhook** — URL.
3. Кнопка **Open in Grafana** открывает те же данные для произвольных разрезов.

## Подводные камни

- API-ключ показывается **ровно один раз**, в момент создания. Восстановить его из консоли
  нельзя — придётся выпустить новый на странице приложения и переподключить SDK.
- Мониторинг сегодня подключается вручную: деплой приложения из GitHub или образа **не**
  создаёт для него приложение мониторинга. Создайте его сами и пропишите OTLP-переменные.
- Тестовый сниппет с curl отправляет текущую секунду как значение счётчика намеренно — так
  консоль рисует настоящую скорость, а не прямую линию. Запустите его несколько раз, чтобы
  увидеть движение на графике.

## Чего пока нет

- Автоматического подключения мониторинга к только что выкаченному приложению — это
  по-прежнему отдельный шаг «Create Monitoring App».
- Своих дашбордов в интерфейсе: в бэкенде это есть, но наружу не выведено — для всего сверх
  встроенных вкладок используйте **Open in Grafana**.
