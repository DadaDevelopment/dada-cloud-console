# Сборки и выкатки

## Зачем это нужно

Под «сборками» живут две связанные, но разные вещи:

1. Страница **Builds** в навигации проекта (`/git`) — все репозитории, подключённые к
   приложениям, одним списком.
2. Вкладка **Deployments** внутри каждого приложения — его собственная история сборок, живые
   логи и откаты.

## Как посмотреть подключённые репозитории

1. Откройте **Builds** в навигации проекта (только Owner и Admin, см. «Подводные камни»).
2. В строке видно: бейдж провайдера (GitHub или GitLab), **имя приложения**,
   **продакшн-ветку**, **корневой каталог**, переопределение фреймворка и бейдж
   **auto-deploy**, если пуши в эту ветку сами запускают сборку.
3. Ссылка **View builds →** ведёт на вкладку **Deployments** нужного приложения.
4. Новый репозиторий подключается кнопкой **Import repository** — тот же путь, что в
   [деплое из GitHub](applications-deploy-from-github.md).

## Как посмотреть историю сборок приложения

1. Откройте приложение → вкладка **Deployments** (или **Settings → Git → View deployments**).
2. Кнопка **Deploy** сверху запускает сборку с последнего коммита отслеживаемой ветки —
   так можно пересобраться без нового коммита.
3. Раздел **Deployments** перечисляет прошлые выкатки, свежие сверху; текущая помечена
   **Current**. Отсюда доступны:
   - **Rollback** — вернуть в бой любую не текущую выкатку.
   - **Promote** — предлагается только для текущей выкатки.
4. Раздел **Builds** перечисляет сами задания сборки: статус, коммит, ветка, что её запустило,
   текст коммита. Клик по строке (или **Logs**) открывает страницу сборки с **живым логом**
   по WebSocket.
5. На странице сборки, пока она идёт, доступна кнопка **Cancel**.

## Подводные камни

- **Кнопки «Retry» у отдельной сборки нет.** После падения нажмите **Deploy** ещё раз на
  странице Deployments (или запушьте коммит, если включён auto-deploy). Это новая сборка с
  текущего HEAD ветки, а не повтор ровно того же коммита.
- **Пункт Builds виден только Owner и Admin**, но сам маршрут импорта — нет: Developer, зашедший
  напрямую на `/git/import`, создаст подключение успешно, просто не увидит его потом в списке
  Builds. Ему остаются вкладки Settings → Git и Deployments внутри приложения.
- **Живые логи требуют настроенной подсистемы сборки** — если её нет, вместо ошибки
  показывается спокойное «пока недоступно».
- **Отключить репозиторий нельзя нигде**, и сменить ветку, корневой каталог или фреймворк
  после импорта в интерфейсе тоже нельзя — только повторный импорт.

## Чего пока нет

- Повтора именно упавшего коммита — только новая сборка с текущего HEAD.
- Отключения репозитория и правки его ветки, каталога и фреймворка после импорта.
- Общей ленты сборок по всему проекту: история у каждого приложения своя.
