# Редизайн агента консоли — утверждённая спека

Статус: утверждено владельцем 2026-08-04. Каждый пункт ниже согласован явно.

## Запрет

Keyword/stem-матчинг для выбора тулов запрещён. Ранжирование по совпадению
подстрок запрещено. Агент выбирает тул по честной схеме и описанию, а не по
обрывкам фраз. Удалено: `searchAliases`, `aliasMatches`, `searchTerms`,
`searchCatalog`, `search_tools`.

## 1. Экспозиция тулов

Массив `tools` фиксирован на всю сессию — при инференсе он сериализуется в
начало промпта (порядок tools → system → messages), поэтому любое изменение
массива инвалидирует префикс-кэш целиком.

- 7 доменных тулов с полной схемой: `listProjects`, `getProject`, `listApps`,
  `getAppState`, `listDatabases`, `getCurrentUser`, `searchLogs`.
- `load_tool(names[])` — возвращает честную swagger-схему перечисленных тулов
  текстом в результат тула. Схема живёт в разговоре, не в массиве.
- `call_tool(name, arguments)` — вызов всего остального. Аргументы валидируются
  локально по той же схеме; ошибка возвращается модели точной формулировкой
  вместе со схемой, чтобы она починилась со второй попытки.
- Полный список остальных имён (без описаний) идёт в системный промпт.

## 2. Список имён

Фильтр = права вызывающего ∩ положительный коэффициент полезности.

- Фаза 1: скоупы токена. Без права записи имена write-тулов не показываются и
  `call_tool` их отклоняет.
- Фаза 2: подрезка по факту из Langfuse — тул, который за N сессий ни разу не
  был загружен и успешно вызван, выпадает из списка.

## 3. Моды агента

`manual` — любая запись через карточку подтверждения.
`edit` (дефолт) — простые операции без подтверждения, опасные через карточку.
`admin` — всё без подтверждения.

Переключатель в строке ввода чата.

## 4. Запись

Очередь подтверждений вместо одиночного pending. Несколько write-вызовов в
одном раунде дают несколько карточек подряд; каждая возвращает модели
настоящий результат или настоящий отказ пользователя. Заглушка
`writeInterruptSkipMessage` удалена.

## 5. Grounding

Отдельной сущности «инвентарь» нет. Preflight остаётся только при пустом
контексте страницы и переиспользует то, что фронт уже загрузил через
react-query. Результат ложится в сессию обычным tool-result.

Сверка id: идентификатор из аргументов проверяется по фактам, уже загруженным
в текущую сессию. Ничего не загружено — сверки нет, тул возвращает честный 404
с подсказкой вызвать `listProjects`.

## 6. Память

Внутри сессии — полная история без окна. Между сессиями — рекурсивное саммари
на пользователя: новое саммари = f(старое саммари, завершённая сессия).

## 7. Хранилище

Postgres для чата уходит. Интерфейс `ChatStore` (история, дневной кап, трейс)
реализуется поверх Langfuse.

Что выяснилось при реализации и чего в спеке не было:

- Langfuse принимает записи асинхронно, а читает eventually consistent. Между
  «сообщение записано в конце хода» и «сообщение видно в начале следующего»
  гарантии нет. Для истории это иногда забытая реплика, для дневного капа —
  потолок с люфтом, а не точный гейт.
- Langfuse для консоли в проде не настроен вообще: ни ключей в values.yaml, ни
  self-hosted инстанса. Единственные ключи в argo-infra принадлежат
  `reels-tracker`. То есть переключение сегодня непроверяемо на живом трафике.
- Чтение — это сетевой вызов в cloud.langfuse.com с инфраструктуры, у которой
  egress уже ронял нас (см. Beget egress timeout), на эндпоинте с бюджетом
  300 мс.

Поэтому переключатель `AGENT_CHAT_STORE` ставится со значением `postgres` по
умолчанию, а неизвестное значение и «langfuse без ключей» откатываются в
postgres с записью в лог. Сессии, саммари и очередь подтверждений в интерфейс
не входят: это условные UPDATE, где ответ — число затронутых строк, то есть
взаимное исключение, которого eventually consistent хранилище не даёт.

## 8. Промпт

Системный промпт статичен и не пересобирается на каждый ход. Динамика
(контекст страницы, саммари, факты сессии) аппендится к сообщению
пользователя. Ограничения агента формулируются в системном промпте как
ограничения, а не как рукописный список «чего я не могу».

## 9. Модель

Anthropic выпиливается. На шлюзе алиасы `claude`/`claude-haiku` вообще не
платформенные — они ходят через BYOK-ключ anthropic проекта `platform`.
Платформа владеет ключом только от `nvidia_nim`; тиры `fast`/`medium`/`smart`
упираются в его per-model лимит (`503 Worker local total request limit
reached`), поэтому для батчей и судьи эвала они непригодны.

Кандидаты: `or-gpt-41-mini` основным, `gpt-4o` верхней планкой для A/B.

2026-08-04: `or-gpt-41-mini` выбыл. Баланс OpenRouter ушёл в ноль, и шлюз
ответил 402 «Insufficient credits» на все 66 вызовов openrouter за три часа —
это все `or-*` алиасы разом, включая `or-gpt-41-mini-online` у reels-tracker.
У группы нет фолбэка (`Available Model Group Fallbacks=None`), поэтому половина
пользователей (когорта A) не получала ответа вообще, а свёртка памяти падала на
каждом тике у всех: `AGENT_CHAT_MEMORY_MODEL` пуст и наследует `AGENT_CHAT_MODEL`.
Основным стал `gpt-4o-mini` (openai напрямую, 200 с настоящим tool-call на живом
каталоге, тот же ценовой класс), `gpt-4o` остался верхней планкой — обе руки
A/B живые. argo-infra `f8778eaf`.

Что из этого следует для спеки: одна модельная группа без фолбэка — это
одна точка отказа на весь продукт, и отказ провайдера выглядит как «агент
молчит», а не как инцидент. Фолбэк настраивается на шлюзе, не в консоли.

## 10. Что не показываем пользователю

Промежуточные сообщения и тул-чипы. В SSE остаются token, confirm_request,
error, done.

2026-08-04: добавлено `navigate`. Ассистент живёт внутри консоли, поэтому ответ
«перейдите по пути /projects/{id}/git/import» оставлял пользователю клик, который
продукт мог сделать сам. Тул `open_console_page` — мета-тул (бэкенд не трогает,
бюджет хода не тратит, подтверждения не требует: состояние платформы не меняется).
Путь проверяется по настоящей таблице роутов на бэкенде и второй раз на фронте:
навигация происходит без клика пользователя, поэтому промах в 404 хуже мёртвой
ссылки. Один переход на ход — модель, которая двигает страницу дважды, уводит её
из-под читающего. На фронте `router.push`, не `location.href`: ответ в этот
момент ещё стримится, полная перезагрузка порвала бы поток
(см. [[project_webkit_redirect_gesture_loss]]).

3. Промпт: статичный префикс, ограничения по образцу, динамика в user-сообщение.

4. Модель: уход с anthropic, A/B. — сделано, 3ce15bc + argo-infra 964cf1be
   (or-gpt-41-mini по умолчанию, gpt-4o на 50% пользователей)
5. Память: сессия + рекурсивное саммари. — сделано, fc1d83b (настоящее
   сообщение коммита — 2207c21) + argo-infra 28fd83e7. Сессия рвётся по
   `AGENT_CHAT_SESSION_IDLE_MINUTES`, по смене скоупа и по очистке контекста;
   внутри сессии история полная, ограничена символами
   (`AGENT_CHAT_HISTORY_MAX_CHARS`), обрезка объявляется модели, а не
   скрывается. Саммари переписывается фоновым циклом под advisory-локом с
   per-user claim, потому что свёртка не идемпотентна;
   `AGENT_CHAT_MEMORY_MAX_CHARS=0` — настоящий выключатель.
6. Хранилище: ChatStore поверх Langfuse. — сделано. `chatStore` (AppendMessage,
   SessionMessages, DailyUserMessageCount) с двумя реализациями: `pgChatStore`
   и `langfuseChatStore` (трейс на сообщение, имя `chat-message-<role>`, кап
   через `meta.totalItems`). Выбор — `AGENT_CHAT_STORE`, по умолчанию
   `postgres`; почему не langfuse — в разделе 7. Чтение возвращает ошибку, а не
   пустую историю: «хранилище не ответило» и «разговор пуст» — разные вещи, и
   свёртка памяти на ошибке чтения больше не помечает сессию свёрнутой.
