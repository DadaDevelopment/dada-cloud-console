# Ночной прогон бенчмарка автоподнимателя

Цель на утро: **число** — сколько из 50 открытых проектов реально встают, и
демо трёх сценариев каталога. Порог владельца: **40+/50**.

## Чем это ограничено (и почему план такой)

Локально нет кредов Console API, а выписывать себе новые запрещено
(`CLAUDE.md`). Значит ступени «собралось/поднялось/отвечает» через прод-песочницу
сегодня ночью недостижимы. Что достижимо без кредов:

- `sourcedetect` — чистый Go по байтам архива, гоняется офлайн на тарболах GitHub.
- Сборка и подъём — локальный docker + buildx (проверено: daemon отвечает,
  buildx v0.31.1).
- HTTP-проба — локально по опубликованному порту.

Это меряет **репозиторий и наше определение**, но НЕ наш Jenkins-пайплайн.
Разница честно называется в отчёте, а не прячется: прогон через прод остаётся
за владельцем (нужен токен песочницы).

## Очередь работ (по одной за итерацию)

- [x] 1. Корпус `tasks/autodeploy-corpus.yaml` — 50 репозиториев с пинами
      коммитов, ожидаемым фреймворком/портом и критерием «живой».
      Формы взяты не из памяти, а проверены: для каждого пина запрошены
      `Dockerfile`/`Procfile`/compose/манифесты через `raw.githubusercontent.com`
      (HTTP 200 = файл есть). Итог: 26 dockerfile-root, 11 no-manifest,
      8 dockerfile-subdir, 5 procfile-only, 2 monorepo-subdir; стеки go 15,
      node 14, python 10, java 3, ruby 2, rust 2, php 2, c 1, dotnet 1.
      Из первичного списка выкинуты библиотеки и фреймворки (django, flask,
      starlette, vite, nuxt, sveltekit, remix, hugo, tailscale): собрать их
      корень не значит поднять приложение, они мерили бы не то.
- [ ] 2. Харнесс `scripts/autodeploy-bench.py`: тарбол по пину → ступень 1
      (детект) → ступень 2 (docker build) → ступень 3 (контейнер жив 60с) →
      ступень 4 (HTTP 2xx/3xx). Причины провала — из фиксированного словаря.
- [ ] 3. Базовый прогон, отчёт `tasks/autodeploy-report-<дата>.md`, коммит.
- [ ] 4. Разбор топ-причин провала, правки в `sourcedetect` / шаблонах
      Dockerfile, повторный прогон. Цель — 40+/50 на ступени 4.
- [ ] 5. Демо трёх сценариев на локальной консоли (`n8n` → иконка, `post` →
      Postgres первым, вставленная ссылка → репозиторий), со скриншотами.

## Правила прогона

- Ничего не создавать в проде. Песочница — только по явной команде владельца.
- Каждый провал имеет причину из словаря; свободный текст запрещён, иначе
  следующий прогон не сравнить с этим.
- Пины коммитов обязательны: бенчмарк без пинов не сравним между запусками.
