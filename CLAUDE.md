# Dada Cloud — правила работы агентов

## Песочница (HARD RULE)

Любое тестирование против прода идёт **только** в проекте `agent-sandbox`
(орг `dada`, id `7a387969-e082-415c-8b61-1f53f7e18295`).

- **НЕ создавать проекты.** Ни через API, ни через консоль, ни через MCP, ни
  «временно, я потом удалю». Каждая сессия думала так — за сутки набралось 24
  мусорных проекта с живыми namespace и томами.
- Нужен ещё один сценарий — заводи **приложение внутри `agent-sandbox`**, не
  новый проект. Лучше переиспользовать одно тестовое приложение.
- Отработал — убери за собой приложение/том/домен в песочнице.
- Чужие проекты (`internal`, `platform`, `example-project`, `alex-personal`,
  клиентские) — read-only. Писать туда только по явной просьбе владельца в
  текущем диалоге.

Гейт продублирован в коде: identity в группе Keycloak `/agents` не владеет
неявной личной оргой и получает 403 `agent_project_creation_denied` на
`POST /api/v1/projects` (см. `backend/internal/auth/jwt.go`,
`backend/internal/api/permissions.go`). Правило здесь — чтобы не упираться в
403 и не искать обход.

## Аналитика

Читать метрики/аудит/косты — группа `/platform-analysts`: доступ ко всем
админ-дашбордам на чтение (`/admin/overview`, `/admin/costs`, ai-usage,
feedback, audit, approvals). Запись в админке остаётся за `/platform-admins`.
Если для аналитики не хватает прав — это баг гейта, чинить гейт, а не выдавать
себе новые креды.

## Креды

Не выписывать себе новых токенов и не расширять группы существующего
сервис-аккаунта. Нужен доступ шире песочницы — спросить владельца.

## Запуск и проверка

Для запуска и визуальной проверки проектов использовать Codex Preview. Не
запрашивать отдельную IDE-конфигурацию запуска.
